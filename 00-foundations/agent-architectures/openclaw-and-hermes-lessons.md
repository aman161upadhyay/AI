# Copy mechanisms, not superiority claims

OpenClaw separates persistent channel/device control from individual model turns. Hermes exposes a general-agent loop with explicit learning artifacts. Neither documentation set establishes a universal reliability or cost winner.

## OpenClaw

The Gateway owns messaging connections and routes sessions. Devices have identities and pairing. Study gateway, sandbox, subagent, and memory boundaries before adding another channel.

Skills use instruction packages with layered roots and dependency metadata. They are not sandboxes. Some skill secrets are injected into the host process for a turn. Align host access, sandbox scope, and credential lifetime.

Current memory documentation includes curated USER.md/MEMORY.md, daily notes, optional DREAMS.md, and background consolidation with provenance gates. Claims that only Hermes has persistent or improving memory are unsupported.

The official showcase describes family meal planning in Notion and a Telegram-driven website migration. These are curated user accounts with search-only verification in the research, not measured reliability studies. They are excluded as evidence for unattended safety.

Marketplace reputation does not establish safe code. Apply pinning, review of network/install behavior, sandboxing, and enforced approval. Specific incident chains were not independently audited here, so this guide does not assign prevalence or remediation versions.

## Hermes

Study `agent/conversation_loop.py`, `prompt_builder.py`, `memory_manager.py`, `context_compressor.py`, `tools/registry.py`, `approval.py`, and `delegate_tool.py` in the repository snapshot.

Hermes combines bounded durable facts, searchable SQLite/FTS5 sessions, and procedural skills. The skill manager can edit procedures and stage writes for review. This is artifact maintenance, not autonomous model-weight improvement.

Memory documentation identifies useful failure cases: a verbal “remembered” acknowledgement without a memory call, a staged write awaiting approval, the wrong profile store, a frozen bootstrap snapshot, and repeated compaction costs in endless sessions. Check receipts, profile, approval status, and session boundary before declaring memory broken or fixed.

Migration from OpenClaw imports selected persona, memory, skills, and settings with backups. Secrets require explicit migration and supported mappings. Imported configuration does not prove equivalent authorization.

## What carries over

Keep the control plane separate from model turns. Use compact discovery metadata and on-demand procedures. Record memory provenance and verify persistence. Stage learned skill changes behind held-out evaluation. End sessions at verified task boundaries.
