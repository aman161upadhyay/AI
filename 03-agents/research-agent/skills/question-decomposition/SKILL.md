# Decompose evidence needs

1. State the decision, audience, time horizon, definitions, and acceptance criteria. Ask at most three material clarifications.
2. Separate required answers from background. For each required answer, specify the observation that could settle it.
3. List plausible alternatives and key assumptions. Under each hypothesis, record predicted evidence and a discriminating search.
4. Add relevant perspectives before fixing the report outline. An implementer may need integration evidence while a reviewer needs evaluation methods.
5. Build a coverage matrix with question ID, importance, evidence needed, candidate origin families, dependency, owner, budget, and state.
6. Keep dependent questions sequential. Parallelize only independent unknowns or distinct evidence families. Avoid assigning the same broad topic to every worker.
7. Give each assignment an objective, exclusions, allowed tools, source guidance, return format, deadline, and share of the global cap.
8. Require atomic claims, exact locators, contrary evidence, access failures, uncertainty, and actual resource use in worker returns.
9. Revisit the tree after discovery. Merge duplicates and replace questions whose premise failed. Preserve the reason in the spine.

Done means every acceptance criterion has a question and evidence plan, not that every branch has an answer. Return the matrix and a short plan that Aman can correct.

Do not use a hypothesis tree to invent facts or force symmetric treatment of a disproven option. Basis: LangChain brief/supervisor structure, STORM perspective discovery, CIA alternative analysis, and Anthropic delegation. See `../../sources.md`.
