# Pick the smallest relevant skill

Give the agent a task outcome, the actual stack, permitted commands and success checks. Ask it to read curated-index.md, choose one procedure, and explain why a near neighbor is unnecessary. Do not load the whole library.

Choose one development process: Addy's lightweight checks are a reasonable starting judgement; Superpowers, Spec Kit, BMAD and Conductor are alternatives. Do not activate their mandatory planners together. Use Hugging Face only for the relevant ML job. Keep the Trail of Bits subtree's attribution and share-alike terms.

## Where each tool looks for skills and instructions, checked 2026-10-25

This is the authoritative loading table for this repository. Project paths are relative to the target project, not this library; `~` means the tool user's home directory. Copy one selected skill directory, including its supporting files and notices, so that the destination contains `<skill-name>/SKILL.md`. Do not copy the catalogue root or add another enclosing `skills/` directory.

Always-on instructions and on-demand skills are different mechanisms. Put the agent's standing contract in the instructions location below; install only the skills needed for the task. Discovery lists usually show available skill metadata, not proof that the model has read every skill body. Verify both discovery and one explicit invocation before trusting the installation.

These are documentation checks, not runtime compatibility results. Record the installed client/SDK version with your discovery check. Loading a file does not enforce its access rules; keep permissions in the host's sandbox and tool dispatcher.

To write your own, start with three real task examples and one near miss. Provide a successful artifact and a failure trace. Follow spec/authoring-guide.md and give the description actual task vocabulary. Bundle reviewed deterministic scripts only if they remove repeated errors.

Evaluate in clean sessions with and without the skill. Keep model, task, tools and budget fixed. Record correctness, unsafe actions, tokens and elapsed time. Use a blind human comparison for style. Repeat runs and hold out new cases. Format validation alone does not justify trust.

Grant read-only repository and redacted evidence access first. Refuse production credentials, unrestricted egress and automatic installers. Approve remote jobs, publication, deletions and deployments separately. Host workflow restrictions override upstream examples that start servers.

Review upstream changes monthly or before a task that depends on a changed API. Compare the pinned full SHA from SOURCE.md to the new commit. Recheck nested licences, inspect changed scripts, hash duplicates and rerun activation plus task evaluations. Replace superseded copies rather than accumulating mirrors. Ask the coding and security agents to review permission changes. You approve promotion and retain a rollback revision.
